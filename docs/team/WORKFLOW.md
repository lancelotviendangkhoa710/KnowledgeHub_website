## 4. Commit Message Convention (CI-enforced)

```

p2: <desc>      TEAM_MEMBER_B
p3: <desc>      TEAM_MEMBER_C
docs: <desc>    documentation
fix: <desc>     bug fix
chore: <desc>   maintenance
hotfix: <desc>  critical fix
```

Not acceptable: `fix`, `update`, `wip`, `changes`.

## 5. Contract-First Development

Define API contract in `docs/API.md` before parallel work begins (~30 min at sprint start).

After an endpoint contract is approved in `docs/API.md`, frontend may mock that exact contract (for example with msw) without waiting for implementation. Do not create mocks for assumed routes, token formats, or response shapes.

When backend is ready: replace only the approved mock with the real endpoint.

## 6. PR Checklist

- [ ] Targets `dev` branch
- [ ] One logical thing, task ID in title
- [ ] Small diff, includes tests
- [ ] CI passes (branch naming + commit convention + Laravel tests)
- [ ] No `dd()`, `var_dump()`, `console.log()`, `.env` committed
- [ ] States: domain, DB changes, API changes, shared files touched
- [ ] CodeRabbit reviewed (CI blocks merge until done)
- [ ] Human reviewer approved (no self-merge)

## 8. Merge Conflict Resolution


## 9. Integration Hotspots

Files most likely to cause merge conflicts:

### `backend/routes/api.php`
- Why: all domains register routes here
- Rule: add only your domain's routes; comment-block them; do not reformat file
- Owner: Shared â€” all add to it; announce in PR description

### `docker-compose.yml`
- Why: single infrastructure definition
- Owner: TEAM_MEMBER_C (p3); others request via chat/PR comment

### `.github/workflows/pr-quality-gate.yml`
- Why: CI affects all PRs
- Owner: INTEGRATION_OWNER_UNASSIGNED
- Rule: team discussion required before any change

### `docs/DATABASE.md` / `docs/ERD.md`
- Why: schema reference for all agents
- Rule: update only after approved migration lands; never speculatively

### `database/seeders/DatabaseSeeder.php`
- Why: root seeder orchestration
- Owner: TEAM_MEMBER_C (p3)
- Rule: feature owners add seeder class; p3 registers in DatabaseSeeder

### `database/migrations/`
- Why: sequential migration files
- Rule: always create a NEW timestamped file; never edit another agent's migration
- Conflict avoidance: unique timestamps generated by `php artisan make:migration`

## 11. Review Process

1. Open PR targeting `dev`
2. CodeRabbit auto-reviews (~2 min)
3. Assign human reviewer (not yourself)
4. Reviewer: checkout branch, run tests, approve or request changes
5. Merge strategy: Squash and Merge
